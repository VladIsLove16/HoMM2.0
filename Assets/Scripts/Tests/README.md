## Структура тестов

### EditMode тесты (быстрые unit тесты)
Запускаются в редакторе Unity и не требуют runtime окружения.

**Расположение:** `Assets/Scripts/Tests/EditMode/`

#### Основные функциональные тесты:
- **UnitModelTests.cs** - тестирует логику UnitModel
- **UnitViewModelTests.cs** - тестирует UnitViewModel и его взаимодействие с моделью  
- **UnitView3DTests.cs** - тестирует UnitView3D компонент

#### Специализированные тесты:
- **UnitModelEdgeCaseTests.cs** - граничные случаи и edge cases
- **PerformanceTests.cs** - тесты производительности критических операций

### PlayMode тесты (интеграционные тесты)
Запускаются в runtime и тестируют реальное взаимодействие компонентов.

**Расположение:** `Assets/Scripts/Tests/PlayMode/`

- **IntegrationTests.cs** - интеграционные тесты взаимодействия всех компонентов

## Зависимости

- NUnit Framework (тестовый фреймворк)
- Unity Test Runner (интеграция с Unity)
- UniRx (через основную сборку Game)

## Как запустить тесты

### В Unity Test Runner:
1. Откройте `Window > General > Test Runner`
2. Выберите вкладку **EditMode** для unit тестов
3. Выберите вкладку **PlayMode** для интеграционных тестов  
4. Нажмите **Run All** или выберите конкретные тесты

### Из командной строки:
```bash
# EditMode тесты
Unity.exe -batchmode -runTests -testPlatform EditMode -testResults results_editmode.xml

# PlayMode тесты  
Unity.exe -batchmode -runTests -testPlatform PlayMode -testResults results_playmode.xml
```

## Категории тестов

### Functional Tests
Основные функциональные тесты, проверяющие корректность работы компонентов.

### Edge Case Tests  
Тесты граничных случаев и необычных входных данных.

### Performance Tests
Тесты производительности для выявления узких мест.

### Integration Tests
Тесты взаимодействия компонентов в runtime окружении.

## Mock объекты

Все тесты используют специально созданные mock объекты для изоляции тестируемого кода:

- **MockDamagable** - для тестирования боевой системы
- **MockStatusEffect** - для тестирования статус эффектов  
- **MockUnitDefinitionSO** - для тестирования определений юнитов
- **MockWorldToCellProvider** - для тестирования преобразования координат
- **MockUnitViewUI** - для тестирования UI компонентов
- **MockAnimator** - для тестирования анимаций

## Архитектурные принципы

Тесты следуют принципам:
- **AAA паттерн** (Arrange-Act-Assert)
- **Изоляция через моки** - каждый компонент тестируется изолированно
- **Один тест - одна проверка** - каждый тест проверяет конкретный сценарий
- **Понятные имена** - названия тестов описывают что и как тестируется
- **Быстрое выполнение** - unit тесты выполняются за миллисекунды
